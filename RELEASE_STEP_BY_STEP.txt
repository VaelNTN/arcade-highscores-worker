STAP 3: BACKEND DEEL B - SUPABASE ONLINE ZETTEN VOOR ECHTE ACCOUNTS & CLOUD-SAVE
================================================================================
Wil je dat spelers en chatters echte ACCOUNTS hebben (inloggen met e-mail,
wachtwoord of Google-login, cloud-opslag van gekochte Gems/Skins, en veilige
profielen over meerdere telefoons heen)? Zo zet je Supabase stap voor stap op:

--- 3A. Supabase Project & Sleutels ---
[ ] 3.1 Ga naar https://supabase.com en log in (bijv. met je GitHub-account).
[ ] 3.2 Klik "New Project":
          - Name:      vaelntn-apps
          - Password:  kies een sterk database-wachtwoord (bewaar dit!)
          - Region:    West EU (Frankfurt of Amsterdam/London)
          - Plan:      Free ($0/maand tot 50.000 actieve gebruikers!)
[ ] 3.3 Wacht 2 minuten tot het project klaar is.
[ ] 3.4 Ga naar "Project Settings -> API" en kopieer:
          1) Project URL       (bijv. https://abcdefgh.supabase.co)
          2) anon / public key (lange JWT sleutel; veilig om in app te gebruiken)
          (GEBRUIK NOOIT de "service_role" key in een frontend/Android-app!)

--- 3B. Accounts & Inlogmethodes Aanzetten ---
[ ] 3.5 Ga in Supabase naar "Authentication -> Providers":
          - Zet "Email" AAN (eventueel "Confirm email" tijdelijk UIT tijdens testen
            zodat mensen meteen zonder e-mailbevestiging kunnen inloggen).
          - Optioneel: Zet "Anonymous Sign-Ins" AAN onder Authentication -> Settings
            zodat nieuwe gebruikers meteen 1-klik kunnen spelen en later hun
            account kunnen koppelen aan e-mail/wachtwoord.
          - Optioneel: Zet "Google" aan als OAuth provider.

--- 3C. Database Tabellen + Beveiliging (RLS) Aanmaken in Supabase ---
[ ] 3.6 Ga in Supabase naar "SQL Editor -> New query", plak dit hele blok en klik RUN:

    -- 1) Gebruikersprofielen (gekoppeld aan Supabase Auth accounts)
    create table if not exists public.profiles (
      id uuid references auth.users on delete cascade primary key,
      nickname text not null default 'Player',
      gender text check (gender in ('man', 'vrouw')),
      country_code text default 'NL',
      languages text[] default array['nl', 'en'],
      gems integer not null default 0,
      is_vip boolean not null default false,
      no_ads boolean not null default false,
      avatar_id integer not null default 0,
      created_at timestamptz default now(),
      updated_at timestamptz default now()
    );

    alter table public.profiles enable row level security;

    create policy "Profielen zijn zichtbaar voor ingelogde gebruikers"
      on public.profiles for select using (true);

    create policy "Gebruiker maakt eigen profiel"
      on public.profiles for insert with check (auth.uid() = id);

    create policy "Gebruiker wijzigt alleen eigen profiel"
      on public.profiles for update using (auth.uid() = id);

    -- Automatisch profiel aanmaken bij elke nieuwe registratie
    create or replace function public.handle_new_user()
    returns trigger as $$
    begin
      insert into public.profiles (id, nickname)
      values (new.id, coalesce(new.raw_user_meta_data->>'nickname', 'Speler'));
      return new;
    end;
    $$ language plpgsql security definer;

    drop trigger if exists on_auth_user_created on auth.users;
    create trigger on_auth_user_created
      after insert on auth.users
      for each row execute procedure public.handle_new_user();

    -- 2) Cloud Save voor Starforge Survivors / Games (voortgang per account)
    create table if not exists public.cloud_saves (
      user_id uuid references auth.users on delete cascade not null,
      app_id text not null,
      save_data jsonb not null default '{}'::jsonb,
      updated_at timestamptz default now(),
      primary key (user_id, app_id)
    );

    alter table public.cloud_saves enable row level security;

    create policy "Alleen eigenaar leest eigen save"
      on public.cloud_saves for select using (auth.uid() = user_id);
    create policy "Alleen eigenaar schrijft eigen save"
      on public.cloud_saves for all using (auth.uid() = user_id);

--- 3D. Hoe je de apps koppelt aan Supabase ---
[ ] 3.7 Zet in elke GitHub repo die Supabase gebruikt (bijv. Starforge / Chat)
        onder Settings -> Secrets and variables -> Actions -> Variables:
          VITE_SUPABASE_URL      = jouw Supabase Project URL
          VITE_SUPABASE_ANON_KEY = jouw Supabase anon key
[ ] 3.8 Installeer in die app-repo:  npm install @supabase/supabase-js
        Maak src/api/supabase.ts:
          import { createClient } from '@supabase/supabase-js';
          export const supabase = createClient(
            import.meta.env.VITE_SUPABASE_URL,
            import.meta.env.VITE_SUPABASE_ANON_KEY
          );
        Account aanmaken werkt dan met 1 regel code:
          await supabase.auth.signUp({ email, password })
        En inloggen met:
          await supabase.auth.signInWithPassword({ email, password })
        Wil je dat ik de Supabase login + cloud-save schermen direct inbouwen in
        specifieke apps (bijv. Starforge Survivors & WorldMatch Chat)? Vraag het
        mij even en geef alleen je publieke VITE_SUPABASE_URL + ANON_KEY (of ik
        bereid het voor met env vars)!

STAP 4: 1 UNIVERSELE UPLOAD KEYSTORE MAKEN (VOOR ALLE 15 APPS!)
================================================================================
Google Play accepteert alleen officieel gesigneerde ".aab" bestanden. Je maakt
ÉÉN sleutelbestand (vaelntn-upload.jks) en bewaart dat HEEL GOED!
(Raak dit bestand nooit kwijt, anders kun je apps later niet meer updaten.)

[ ] 4.1 Zorg dat Java (JDK) geinstalleerd is op je PC.
[ ] 4.2 Draai in je terminal:
          keytool -genkeypair -v -keystore vaelntn-upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
        Beantwoord de vragen en onthoud je wachtwoorden goed!
[ ] 4.3 Maak Base64 tekst van de keystore:
        - Windows PowerShell:
            [Convert]::ToBase64String([IO.File]::ReadAllBytes("vaelntn-upload.jks")) | Out-File -Encoding ascii keystore.b64.txt
        - Linux / Git Bash:
            base64 -w 0 vaelntn-upload.jks > keystore.b64.txt
        - macOS:
            base64 -i vaelntn-upload.jks | tr -d '\n' > keystore.b64.txt

[ ] 4.4 Voeg in ELKE GitHub-repo (zie overzicht in Stap 7) deze 4 Secrets toe
        via: Repo -> Settings -> Secrets and variables -> Actions -> Secrets:
          1) ANDROID_KEYSTORE_BASE64   = volledige inhoud van keystore.b64.txt
          2) ANDROID_KEYSTORE_PASSWORD = je keystore wachtwoord
          3) ANDROID_KEY_ALIAS         = upload
          4) ANDROID_KEY_PASSWORD      = je key wachtwoord

        TIP: Heb je GitHub CLI ("gh") geinstalleerd? Dan kan het met een script
        voor alle repo's tegelijk i.p.v. 60 keer klikken!

STAP 8: 12 TESTERS VOOR 14 DAGEN REGELEN (VERPLICHT VOOR NIEUW PERSONAL ACCOUNT)
================================================================================
Google Play eist bij een nieuw persoonlijk account dat elke app eerst 14 dagen
door minstens 12 mensen is geinstalleerd in "Closed testing" voordat hij live
mag naar Production. De slimste truc:

[ ] 8.1 Ga naar https://groups.google.com -> Klik "Create group":
          Naam:     vaelntn-android-testers
          Toegang:  "Anyone on the web" mag lid worden.
[ ] 8.2 Ga voor elke app in Play Console naar:
        "Testing -> Closed testing -> Manage track -> Testers -> Google Groups"
        Plak daar HETZELFDE e-mailadres: vaelntn-android-testers@googlegroups.com
[ ] 8.3 Upload per app je gesigneerde "app-release.aab" (uit GitHub Actions ->
        Artifacts -> app-release-aab) en druk "Send changes for review".
[ ] 8.4 Kopieer na goedkeuring van elke app de "Join on the web" testlink.
[ ] 8.5 Plaats op Reddit r/AndroidClosedTesting (of app Testers Community) een
        oproep met jouw 1 Google Group link + testlinks van je apps. Binnen 2
        dagen heb je 12-20 testers die via die ene Google Group al je apps
        tegelijk testen (en jij test hun apps even terug!).
